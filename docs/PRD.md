# Activity QR Voucher System — PRD

Version: 1.1.0\
Status: Core Business Rules Confirmed  
Event Type: Single Event  
Timezone: Asia/Taipei

## 1. Product Objective

建立一次性活動 QR Code 憑證管理與商品核銷平台，提供：

- 活動人員批次產生實體 QR Code。
- 消費者現場領取並啟用入場憑證。
- 前 1,000 位成功啟用的消費者取得免費商品兌換資格。
- 攤販使用 WebApp 掃描 QR Code 及核銷商品。
- 每份免費兌換資格於所有攤販間共用，只能成功核銷一次。
- 財務及活動人員查看統計與匯出核銷資料。

## 2. User Roles

### Participant

- 持有實體 QR Code。
- 透過 WebApp 查看入場及免費資格狀態。
- 可在任一符合活動規定的攤販進行免費兌換。
- 每份免費資格僅能使用一次。

### Vendor

- 登入攤販 WebApp。
- 掃描消費者 QR Code。
- 查詢免費資格是否有效。
- 確認交付商品並執行核銷。
- 查看自己攤位的核銷數量與紀錄。

### Event Staff

- 管理活動、攤販及 QR Code 批次。
- 執行憑證啟用、作廢及有權限的補發。
- 查詢免費資格發放狀況。
- 監控整體活動進度。

### Finance Staff

- 查詢各攤販核銷數量。
- 匯出核銷報表。
- 查看財務核對紀錄。
- 預設不得建立、作廢或修改兌換資格。

## 3. Admission Activation Rules

Business Rule: BR-001

1. QR Code 建立時不自動取得免費資格。
2. 每張有效入場憑證只能成功啟用一次。
3. 啟用順序由後端資料庫成功提交的序列化啟用交易決定，不依賴前端時間。
4. 第 1～1,000 位成功啟用者取得免費兌換資格。
5. 第 1,001 位開始不再取得免費資格，但仍可以正常啟用入場憑證。
6. 不允許因為並發啟用產生第 1,001 份免費資格。
7. 重複啟用同一張憑證不可再次增加啟用序號。
8. 已分配的啟用順序不得修改或重排。

啟用成功後，API 回傳：

- 是否啟用成功。
- 啟用序號。
- 是否取得免費資格。
- 免費資格狀態。

## 4. Free Redemption Rules

Business Rule: BR-002

1. 一張入場憑證最多對應一份免費兌換資格。
2. 一份免費兌換資格只能成功核銷一次。
3. 所有攤販共用該資格，不以攤販為單位重置。
4. 攤販掃碼查詢只進行驗證，不消耗資格。
5. 攤販確認商品已交付後，才執行實際核銷。
6. 成功核銷必須記錄對應攤販及操作人員。
7. 核銷成功後，資格立即變成 REDEEMED。
8. 其他攤販再次核銷時，必須回傳 ALREADY_REDEEMED。
9. 多個攤販同時核銷時，最多一筆可以成功。
10. 網路重試不得產生重複核銷紀錄。

## 5. Credential State

入場憑證狀態：

- CREATED：已產生，尚未啟用。
- ACTIVATED：已啟用。
- VOIDED：已作廢。

免費兌換資格狀態：

- NOT_ELIGIBLE：不具免費資格。
- AVAILABLE：具資格且尚未兌換。
- REDEEMED：已完成兌換。
- REVOKED：資格已撤銷。

入場憑證狀態與免費兌換資格狀態必須分開管理。

## 6. Vendor Redemption Flow

1. 攤販登入 WebApp。
2. 掃描消費者實體 QR Code。
3. 前端傳送驗證請求。
4. 後端驗證憑證、活動、免費資格與攤販權限。
5. 前端顯示可兌換或不可兌換。
6. 攤販確認商品交付。
7. 後端使用資料庫交易執行核銷。
8. 成功後儲存 Redemption 紀錄。
9. 後台統計更新。

## 7. Dashboard Metrics

活動統計：

- 已產生 QR Code 數量。
- 已啟用入場憑證數量。
- 免費資格累計發放數量。
- 尚可核發免費資格名額。
- 已兌換數量。
- 未兌換免費資格數量。
- 各攤販兌換數量。
- 各攤販兌換占比。
- 核銷時間紀錄。

免費資格名額上限固定為 1,000。

未兌換資格數量不等於可以重新發放的資格名額。

## 8. Acceptance Criteria

- AC-001：可批次建立唯一 QR Code。
- AC-002：首次啟用成功時分配唯一啟用序號。
- AC-003：第 1,000 名可取得免費資格。
- AC-004：第 1,001 名不得取得免費資格。
- AC-005：併發啟用不會造成免費資格超發。
- AC-006：同一憑證重複啟用不增加名額消耗。
- AC-007：合格消費者可在任一授權攤販核銷一次。
- AC-008：核銷成功後所有攤販均不得再次核銷。
- AC-009：多個攤販同時核銷時最多一筆成功。
- AC-010：攤販核銷紀錄包含攤販、時間及操作人員。
- AC-011：後台統計與成功核銷紀錄一致。
- AC-012：財務可依攤販匯出正確核銷數量。
- AC-013：未授權使用者不得執行啟用管理或核銷。
- AC-014：無效、未啟用及作廢的 QR Code 不得完成核銷。

## 9. Default Operational Policy

為避免名額歧義，MVP 暫定：

- 免費資格一旦核發，即計入 1,000 人上限。
- 已核發資格即使作廢，也不會自動釋放名額給下一位參加者。
- 補發不得建立第二份免費資格。
- 需要重新分配或恢復資格時，必須經過明確核准的管理流程。

本節屬於預設營運政策，仍需活動主辦方確認。

## 11. Confirmed MVP Implementation Scope

2026-11-19 使用者確認：QR 由活動人員從後台產生並印成實體憑證，工作人員現場掃碼啟用，再由登入攤販掃碼驗證並確認核銷。參考畫面用於介面設計，顯示數字來自資料庫，不以示範數據作為正式統計。

已核准 React／Node.js／PostgreSQL 實作、交易式啟用與核銷資料模型、工作人員／攤販／財務帳密登入，以及可重新下載 24 小時的加密列印暫存。必要 API 可由實作者自行補充並同步文件與測試；業務規則與資料庫變更仍須先取得核准。

首版提供批次列印、工作人員啟用、攤販驗證與確認核銷、統計與 CSV 匯出。帳號和攤位由管理 CLI 建立及指派。尚不提供補發、作廢、撤銷、名額重分配、商品品項限制與結算金額操作。

軟體核銷介面遵循先驗證、再明確確認核銷；現場實際交付商品與核銷成功的時序、異常交付處理，仍須主辦方訂定作業程序。
