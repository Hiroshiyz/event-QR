# MVP 程式碼審查紀錄

日期：2026-11-19。PR：<https://github.com/Hiroshiyz/event-QR/pull/1>，目標 staging。

本次為實作代理逐檔自審與回歸測試，不是獨立的人類或第三方審查。使用者已明確授權本次審查完成、檢查通過後合併至 staging；不授權正式部署，也不改變後續業務規則與資料庫需先核准的要求。

## 發現及修正

| 嚴重度 | 問題 | 修正與證據 |
| --- | --- | --- |
| P1 | 批次建立成功後，列表更新失敗被當作建立失敗；原名稱保留可能導致重按新增第二批 | 成功後立即保留收據、清除建立表單名稱，獨立處理列表錯誤，收據提供列印入口。Chromium 中故意中斷列表請求，驗證資料庫仍只有一批且可列印 |
| P1 | 先前結果不明時，重試遇到 429／登入限制會丟失原冪等鍵 | 保留尚未確認的原鍵與使用者範圍，401／403／408／425／429 及鍵衝突不當作終局結果。單元測試驗證 500→429→401→重新登入後仍用同一鍵 |
| P2 | 舊帳號的延遲回應可能清除新帳號待處理的請求 | 請求完成只清除原使用者與原鍵對應的紀錄；登入／登出不刪除未知結果。測試同時保留另一帳號的未確認請求 |
| P2 | ROLLBACK 本身失敗時，可能將損壞連線放回 pool，並掩蓋原始 COMMIT 錯誤 | 將故障連線以 release(error) 丟棄，保留原始錯誤；單元測試模擬提交及回滾均失敗，另回歸實際 PostgreSQL 交易測試 |

未變更資料庫 schema、免費上限、資格核發或跨攤一次性規則。API 契約保持相容，只修正前端恢復與交易連線管理。

## 保留限制與下一步

目前仍為單程序記憶體 IP 限流，反向代理若把所有使用者集中到同一來源 IP，需在正式部署前驗收限流容量及可信代理設定；此 PR 不自行更改已核准安全策略。

真實手機、相機權限、紙張、光線、PDF 分頁與印刷縮放需要現場人工驗收。合併後先實作唯讀的上線前檢查與現場驗收文件，不自行部署，不補做未核准營運流程。
