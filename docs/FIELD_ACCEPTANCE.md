# 上線前檢查與現場驗收

本文件適用於已核准的單一活動 MVP。自動化測試已覆蓋資料庫交易與並發，但不代表真實手機、紙張、光線或場地網路已驗收。所有勾選預設未完成，由現場負責人記錄結果；不得預先填成通過。

## 1. 測試與正式環境邊界

- 使用隔離的測試活動、資料庫與測試帳號進行演練，先核對環境網址，避免消耗正式免費名額或商品。
- 不重設正式計數器、不刪除核銷歷史、不直接修改資格來重做測試。正式規則仍為前 1000 位成功啟用及跨攤一次性核銷。
- 測試 QR、列印 PDF、相機視訊與照片都視為敏感憑證；不能提交 Git、貼入 issue、PR、日誌或一般訊息。結果只記公開核對碼。
- 正式部署、業務規則與資料庫變更仍須另行核准。本次準備工作不包含部署。

## 2. 自動檢查

在設定好對應環境後執行：

```sh
npm run preflight
npm run --silent preflight -- --json
```

指令只讀取資料庫及 migration 清單，使用 REPEATABLE READ READ ONLY 快照與查詢逾時。不套用 migrations、不建立帳號、不啟用、不核銷、不清除資料，也不輸出原始 QR token、帳密、Cookie、金鑰或連線字串。

FAIL 對應結束碼 1，須先由負責人調查。WARN 需要人工確認，沒有 FAIL 只代表自動檢查完成，不代表可上線。若出現資料不一致，不可用刪除歷史或重新分配序號修復。

檢查包括：設定、PostgreSQL 版本、必要資料表與 migrations、唯一約束與保護 trigger、活動與啟用計數、1000 份上限、核銷／資格一致性、冪等結果、工作人員與攤販指派、列印金鑰可解密性及到期列印暫存。金鑰驗證只在記憶體處理秘密，不輸出內容。

## 4. 帳號與環境

- [ ] 工作人員可登入並進入後台及入場啟用頁。
- [ ] A／B 攤販各自只能操作被授權的攤位；財務只能讀取統計與匯出。
- [ ] 未登入不能啟用或核銷，停用帳號及過期 Session 不能操作。
- [ ] 手機使用正式 HTTPS 測試來源；不以一般 HTTP 的內網 IP 代替。
- [ ] 確認反向代理及限流：多台手機不會因全部被視為單一代理 IP 而互相封鎖。若需更改可信代理或安全設定，先提出具體方案核准。
- [ ] 核對主辦方帳號名冊、攤販指派與財務讀取權限，不使用共用預設密碼。

## 5. QR 列印

- [ ] 在測試活動建立一批至少 12 張 QR，確認建立本身沒有免費資格。
- [ ] 列印／另存 PDF，確認每張公開碼唯一、QR 完整且四周留白。
- [ ] 檢查多頁分頁：卡片與 QR 不被裁切，不重複頁面或漏張。
- [ ] 記錄紙張與列印比例；以 100% 實際大小測試，避免預設縮放使 QR 太小。
- [ ] 在預計使用的距離、光線及角度，以 iPhone、Android 各讀取數張實體紙本；不要只掃螢幕。
- [ ] 主辦單位確認列印檔保管、印刷剩餘品與重複列印件的處理，避免同一憑證發給不同人。
- [ ] 24 小時內可授權再次列印，財務／攤販不能下載；到期不能下載。到期案例用隔離測試資料或自動化證據，不修改正式紀錄。

## 6. 工作人員現場啟用

- [ ] 相機第一次允許權限後可掃描；拒絕權限時有提示且可使用完整憑證輸入。
- [ ] 關閉掃描介面後鏡頭停止；重新開啟可繼續使用。
- [ ] 掃描尚未啟用的實體 QR，確認後顯示序號與免費資格，後台計數正確。
- [ ] 同張 QR 重掃保持原序號、不再增加已啟用及已核發數量。
- [ ] 兩位工作人員同時掃同張 QR，結果仍只有一次啟用。
- [ ] 1000／1001 邊界與 100 筆並發沿用 CI／PostgreSQL 測試證據；需要現場重做時，只在隔離資料庫進行，不改正式上限或序號。

## 7. 攤販核銷

- [ ] 未啟用憑證在 A 攤不能兌換。
- [ ] 已啟用且合格的 QR 在 A 攤顯示可兌換；只驗證、不按確認時資格仍可使用。
- [ ] 按「確認交付並核銷」後顯示成功，只有一筆紀錄，時間與操作攤位正確。
- [ ] 同張 QR 在 B 攤再次掃描顯示已使用，不能再次核銷。
- [ ] A／B 同時對同張合格 QR 確認，只有一攤成功，其他顯示已使用。
- [ ] 快速連按、逾時與原請求重試不增加第二筆成功紀錄。
- [ ] 不合格、無效憑證不能核銷；公開碼本身不能代替私密 QR token。
- [ ] 主辦方確認現場商品交付與按確認的操作順序，以及核銷成功但尚未交付、網路中斷等異常處理。未確認前不自行設計補發或撤銷流程。

## 8. 網路與恢復

- [ ] 測試送出前斷線、送出後回應遺失兩種情況，先查結果再以原內容重試。
- [ ] 重新整理後再掃原張 QR，能沿用原請求鍵；不把逾時直接當作失敗重做。
- [ ] 遇到限流或重新登入，原未確認請求鍵仍保留。
- [ ] 批次已建立但列表更新失敗時，仍看得到成功收據且可列印，不要求重新建立。
- [ ] 記錄恢復結果只使用公開碼，不收集包含私密 QR 的網路 HAR、螢幕截圖或日誌。

## 9. 報表與營運放行

- [ ] 以少量測試核銷核對各攤及總量，失敗、重複掃描及重送不增加成功總數。
- [ ] CSV 可由財務開啟，時間為 Asia/Taipei 且資料正確，不包含 QR token、token hash 或登入資訊。
- [ ] 確認金鑰備援、資料庫備份及隔離環境還原演練；不要把備份內容貼入 Git。
- [ ] 確認到期列印與 Session 清理排程；過期列印即使尚未清理也不能下載。
- [ ] 保留核銷與稽核歷史，訂定事故聯絡方式與人工處理責任人。
- [ ] 全部 FAIL 已解決、WARN 有負責人與處置，主辦方完成人工驗收並明確批准部署。

## 10. 本次準備的範圍

本階段提供自動唯讀檢查與這份待執行清單，沒有宣稱現場驗收通過。尚未決定的補發、撤銷、名額重分配、商品限制與金額結算保持原狀。任何新業務或資料庫方案需先核准，不能因驗收方便而開放繞過授權或重設歷史。
